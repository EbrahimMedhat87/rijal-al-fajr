# رجال الفجر — تطبيق تسجيل الحضور

تطبيق ويب (PWA) بالعربية وRTL يستبدل ورقة الحضور اليومية. المنظمون فقط يسجّلون الحضور؛ الأطفال لا يملكون حسابات.
يعمل على أكثر من موبايل بقاعدة بيانات واحدة، ويسجّل الحضور **بدون إنترنت** ثم يزامن تلقائيًا.

**الـ stack:** React + TypeScript + Vite · Tailwind CSS · Supabase (Postgres + Auth + RLS) · IndexedDB (Dexie) · PWA · Vercel

---

## 1) التشغيل المحلي

```bash
npm install
cp .env.example .env.local     # ثم ضع قيم مشروع Supabase
npm run dev
```

القيم من Supabase: **Project Settings → API**: `Project URL` و `anon public key`.
لا تضع `service_role` في الواجهة أبدًا — التطبيق لا يحتاجه.

أوامر الفحص:

```bash
npm run typecheck   # TypeScript
npm test            # 114 اختبار: التواريخ، الفترات، الترتيب (أطفال/مساجد)، CSV، المزامنة، الأخطاء، استيراد القوائم
npm run build       # بناء الإنتاج + service worker
npm run test:db     # اختبارات SQL/RLS على Postgres محلي (يحتاج psql وصلاحية superuser)
```

## 2) إعداد Supabase (مرة واحدة)

1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com) (الخطة المجانية تكفي).
2. من **SQL Editor** شغّل الملفات بالترتيب (انسخ محتوى كل ملف والصقه ثم Run):
   1. `supabase/migrations/0001_schema.sql` — الجداول والقيود والـ triggers
   2. `supabase/migrations/0002_functions.sql` — دوال الصلاحيات وتسجيل الحضور والإبطال
   3. `supabase/migrations/0003_rls.sql` — سياسات Row Level Security
   4. `supabase/migrations/0004_mosques.sql` — المساجد، ربط المنظمين بمساجدهم، ترتيب المساجد، طلبات التسجيل
   5. `supabase/migrations/0005_add_participant_rpc.sql` — إضافة طفل بمعرّف من الجهاز (للإضافة بدون إنترنت)
   7. `supabase/migrations/0007_delete_participant.sql` — حذف طفل نهائيًا مع كل حضوره (المالك، والمشرف لأطفال مسجده) مع حفظ لقطة في سجل التدقيق
   6. `supabase/migrations/0006_child_numbers_undo.sql` — رقم لكل طفل داخل مسجده (الجديد يملأ أصغر رقم فاضي، والمنقول يأخذ آخر رقم + 1) والبحث به، إلغاء الحضور، كشف التكرار بين المساجد، نقل الطفل مع سجله
3. **التسجيل الذاتي للمنظمين:** اترك Authentication → Sign In / Providers → Email → **Allow new users to sign up** مفعّلًا. الأمان لا يعتمد على إغلاقه: أي حساب جديد **لا يرى أي بيانات** حتى يوافق عليه المالك ويربطه بمسجد (راجع القسم 4). يُفضّل تعطيل **Confirm email** لتسهيل الأمر (الموافقة اليدوية من المالك هي الحماية).
4. **أنشئ حساب أول مالك:** Authentication → Users → **Add user** → ضع البريد وكلمة مرور قوية وفعّل **Auto Confirm User**.
5. من **SQL Editor** اربط هذا الحساب بدور المالك وأنشئ المبادرة:

```sql
select public.bootstrap_first_owner(
  'owner@example.com',          -- نفس بريد الحساب الذي أنشأته
  'اسمك',                        -- الاسم الظاهر
  'رجال الفجر',                  -- اسم المبادرة
  date '2026-12-01',            -- تاريخ بداية المبادرة
  'Africa/Cairo'
);
```

الدالة تعمل **مرة واحدة فقط** (ترفض لو يوجد أي منظم)، وغير متاحة لأي مستخدم من التطبيق أو الـ API؛ لا تُنفَّذ إلا من SQL Editor.

6. أضف المساجد: **القائمة ← الإدارة ← المساجد ← إضافة**.
7. أضف المنظمين: كل منظم يفتح الرابط ويضغط **"منظم جديد؟ أنشئ حسابك"** ويكتب اسمه وبريده، فيظهر لك في **الإدارة ← طلبات تسجيل جديدة**. اضغط **قبول** وحدد الدور والمسجد (أو أكثر من مسجد).
   نسيان كلمة المرور: من لوحة Supabase (Authentication → Users).
8. أضف الأطفال: **الأطفال ← 📥 استيراد** ثم الصق كشف المسجد (أو ارفع ملف .txt/.csv) وراجع المعاينة ثم أضف.

## 3) النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. في Vercel: **Add New → Project** → اختر المستودع (يكتشف Vite تلقائيًا، و`vercel.json` جاهز).
3. أضف Environment Variables: `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
4. Deploy. ثم في Supabase: Authentication → URL Configuration → ضع رابط Vercel في **Site URL**.
5. على الموبايل: افتح الرابط في Chrome (أندرويد) أو Safari (آيفون) → **Add to Home Screen**.

> **مهم:** افتح التطبيق وسجّل الدخول **مع الإنترنت مرة واحدة** على كل جهاز قبل الاعتماد على العمل بدون إنترنت (لتحميل قائمة الأطفال وتخزين التطبيق).

## 4) الأدوار

| الإجراء | مالك | مشرف | مسجِّل |
|---|:-:|:-:|:-:|
| نطاق الرؤية | كل المساجد | مساجده فقط | مساجده فقط |
| تسجيل الحضور | ✓ (أي تاريخ) | ✓ (أي تاريخ) | ✓ (اليوم وأمس فقط) |
| إضافة/استيراد/تعديل/إيقاف الأطفال | ✓ (أي مسجد) | ✓ (مساجده) | — |
| نقل طفل بين مساجد | ✓ | بين مساجده فقط | — |
| ترتيب الأطفال (على كل المساجد) | ✓ | ✓ | — |
| ترتيب المساجد (متوسط أيام الحضور للطفل) | ✓ | ✓ | — |
| التقارير وCSV | ✓ | ✓ (مساجده) | — |
| سجل الحضور لكل طفل + إبطال سجل (بسبب) | ✓ | ✓ | — |
| سجل التدقيق | ✓ | ✓ | — |
| إدارة المساجد والمنظمين وإعدادات المبادرة وقبول الطلبات | ✓ | — | — |

**لماذا لا "رقم/كود المسجد" بدل الحساب؟** الكود يُنسخ ويُشارَك فيكشف أسماء الأطفال لأي شخص، ولا يميّز مَن سجّل الحضور ولا يمكن سحبه من شخص معيّن. لذلك لكل منظم حساب (بريد + كلمة مرور) والمالك يربطه بمسجده؛ عزل المساجد مفروض في قاعدة البيانات نفسها.

كل هذا مفروض **في قاعدة البيانات** (RLS + دوال security definer)، وليس بإخفاء الأزرار فقط. حتى لو تجاوز أحدهم الواجهة واستدعى الـ API مباشرة، يرفضه الخادم.

## 5) قواعد الحضور

- **سجل صالح واحد لكل طفل في اليوم**: قيد فريد في قاعدة البيانات (`attendance_one_valid_per_day`).
- كل عملية لها `client_op_id` فريد من الجهاز: إعادة الإرسال بعد انقطاع لا تُنشئ تكرارًا.
- **لا حذف للحضور**: التصحيح بالإبطال مع سبب إجباري، ويُكتب في `audit_log`، ويمكن بعده تسجيل الحضور الصحيح.
- إيقاف الطفل لا يحذف تاريخه (وحذف طفل له حضور مستحيل بالـ foreign key).
- التواريخ `date` فقط (`YYYY-MM-DD`) بتوقيت المبادرة (`Africa/Cairo`)، و"اليوم" يُحسب على الخادم وعلى الجهاز بنفس المنطقة الزمنية، فلا يتأثر بتوقيت الموبايل.
- الترتيب يُحسب دائمًا من السجلات الصالحة في الفترة (لا عدّادات يدوية). التعادل بترتيب تنافسي (1، 1، 3)، ومن بلا حضور في الفترة لا يُرتَّب.
- **الربع = ربع تقويمي** (يناير–مارس، أبريل–يونيو، يوليو–سبتمبر، أكتوبر–ديسمبر).
- الجوائز يدوية بالكامل: التطبيق لا يحدد فائزين ولا قواعد جوائز.

## 6) كيف يعمل العمل بدون إنترنت

1. الضغط على "حاضر" يحفظ العملية فورًا في IndexedDB ويعرض **"محفوظ على الجهاز — بانتظار المزامنة"**.
2. تُرسَل تلقائيًا عند: فتح التطبيق، عودة الاتصال، العودة للتطبيق، كل 20 ثانية لو يوجد معلّق، أو زر **مزامنة الآن**. (لا نعتمد على Background Sync؛ المزامنة تعمل أثناء فتح التطبيق.)
3. لا تُعلَّم العملية **synced** إلا بعد تأكيد الخادم. عند انقطاع الاتصال تبقى `pending` ولا يُحذف شيء.
4. جهازان سجّلا نفس الطفل/اليوم: يُقبل الأول، والثاني يأخذ `already_recorded` فيظهر للمنظم "سُجِّل مسبقًا من جهاز آخر"، والعدّاد سليم.
5. رفض نهائي من الخادم (مثلًا تاريخ غير مسموح) ⇒ حالة **فشل** تظهر في الرئيسية مع "إعادة المحاولة" أو "حذف" (بقرار المنظم فقط).
6. تسجيل الخروج يمسح قائمة الأطفال المخزنة (خصوصية الأجهزة المشتركة)، لكن يُبقي أي سجلات لم تُزامَن بعد (معرّفات فقط) حتى لا تضيع.

## 7) الخصوصية

نخزّن اسم الطفل وحضوره فقط: لا صور، لا عناوين، لا أرقام هواتف. لا شيء عام: كل الجداول مقفلة على `anon`، والقراءة للمنظمين النشطين فقط، والمسجِّل لا يرى سوى حضور اليوم وأمس.

## 8) قائمة فحص يدوية (على الأجهزة الحقيقية)

- [ ] تسجيل حضور أونلاين، ثم محاولة تسجيل نفس الطفل مرة ثانية ⇒ الزر معطّل.
- [ ] تثبيت التطبيق (Add to Home Screen) على آيفون وأندرويد.
- [ ] وضع الطيران ⇒ تسجيل 3 أطفال ⇒ إغلاق التطبيق تمامًا ⇒ فتحه (ما زال أوفلاين) ⇒ السجلات ما زالت "بانتظار المزامنة" ⇒ إيقاف وضع الطيران ⇒ تتزامن وتظهر "كل شيء متزامن".
- [ ] جهازان أوفلاين يسجلان نفس الطفل ⇒ بعد الاتصال يوجد سجل واحد، وجهاز منهما يعرض "سُجِّل مسبقًا".
- [ ] قطع الإنترنت أثناء المزامنة ⇒ لا يضيع شيء وتُعاد المحاولة.
- [ ] الترتيب عبر حدود الشهر (آخر/أول الشهر) والربع (31 مارس/1 أبريل) والسنة، وتعادل بين طفلين.
- [ ] مسجِّل: لا يرى الترتيب ولا التقارير ولا الإدارة، ويفتح `/rankings` يدويًا فيُعاد للرئيسية.
- [ ] إنشاء حساب منظم جديد من صفحة الدخول: يدخل فيجد "في انتظار الموافقة" ولا يرى أي أطفال؛ المالك يقبله ويربطه بمسجد فيرى مسجده فقط.
- [ ] منظم مسجد (أ) لا يرى أطفال مسجد (ب) ولا ترتيبه التفصيلي، لكنه يرى ترتيب الأطفال العام وترتيب المساجد.
- [ ] استيراد كشف حقيقي: الأسماء تُنظَّف من الأرقام وعلامات ✓✗، والمكرر يُستبعد.
- [ ] تصدير CSV وفتحه في Excel/Sheets والتأكد أن العربية سليمة.
- [ ] مراجعة الشاشات على موبايل صغير (الاتجاه RTL، لا تمرير أفقي، الأزرار تُضغط بإبهام واحد).

**لم يُختبر (يلزم قبل الاعتماد الكامل):**
- لم يُشغَّل على **مشروع Supabase حقيقي** ولم يُنشر على Vercel (لا توجد بيانات اعتماد هنا). أول تشغيل يحتاج تجربة الخطوات في القسم 2 كاملة.
- لم يُجرَّب على **آيفون/أندرويد حقيقيين** (فقط محاكاة Chromium). خاصة تثبيت الـ PWA وسلوك Safari مع IndexedDB.

## 10) قيود وقرارات يجب معرفتها

- تسجيل الدخول نفسه يحتاج إنترنت. بعدها يبقى الجهاز مسجّلًا ويعمل بدون إنترنت.
- **المسجِّل** يستطيع التسجيل لليوم وأمس فقط. لو بقي جهاز مسجِّل بدون إنترنت أكثر من يومين، تُرفض سجلاته الأقدم وتظهر "فشل"، وعلى المشرف إدخالها يدويًا بتاريخ سابق.
- **إضافة طفل جديد تعمل بدون إنترنت**: يُحفظ على الجهاز ويظهر في التحضير فورًا، ويُرسَل قبل حضوره عند عودة الاتصال. أما تعديل الأطفال والاستيراد الجماعي والإبطال والترتيب والتقارير والإدارة فتحتاج إنترنت.
- **تنبيه التكرار بين المساجد:** عند إضافة اسم، لو أول 3 كلمات منه (بعد توحيد الهمزات والتاء المربوطة) مطابقة لطفل في مسجد آخر يظهر تنبيه باسمه ومسجده (لا يمنع الإضافة). وفي الاستيراد يُستبعد المشابه افتراضيًا.
- أيقونات التطبيق مولَّدة بسيطة (هلال/دائرة ذهبية على أخضر) وليست هوية نهائية؛ استبدل `public/icon-192.png` و`public/icon-512.png` و`public/icon.svg`.
- الأطفال المتشابهة أسماؤهم: لا يوجد معرّف إضافي (لأننا نخزّن الاسم فقط)؛ فرّق بينهم بحرف أو لقب في الاسم.
